How I work, in four steps

  1. 01Listen
  2. 02Map the As-Is
  3. 03Design the To-Be

It starts with the right questions.

I lead discovery sessions with the people who do the work. Wispr Flow captures every session, so my attention stays on the detailed questions that show how a process really runs.

QWho receives the request first?

  • Who receives the request first?
  • Where does it wait, and for how long?
  • Which checks are still done by hand?
  • What happens when a document is missing?
  • Who has to approve it, and why?

Map how work happens today.

Every hand-off, approval and re-check goes into an As-Is model. Claude helps me structure it into minutes and requirements the client recognises as their own.

Propose a leaner way to work.

I propose To-Be workflows that remove duplicate steps and shorten waits, then prototype them with Claude Code so stakeholders can react to something real before the build.

Let the system carry the routine.

Steps that need no judgment get automated, so people spend their time on decisions. I write the stories in Azure DevOps, work with the developers and test until it ships.

Example process, document approval. As-Is: 12 steps, 8 of them manual, with two rework loops: request arrives by email, logged in a spreadsheet, forwarded to a reviewer, documents checked by hand, missing documents chased (looping back to the start), re-keyed into the system, a three-day wait for the manager, print sign and scan, a second review (looping back to the document check), archived in a shared folder, requester emailed, done.

An AI agent flags duplicates, manual re-keying, waits and loops.

To-Be: 6 steps across three lanes. Requester: request via portal. AI agent: intake and logging, then completeness check. Team: one-click approval. AI agent: auto archive and notify. Requester: done. One manual step, no rework loops.
